# 让智能体帮你写一条记忆

导出是「把已有的搬过来」。这篇讲的是另一种：**从零做一条**。

> 想先看看已经有哪些记忆，看 [find-memory.md](find-memory.md)；要把别的助手的东西导进来，看 [export-prompt.md](export-prompt.md)。

四种方法，取决于你手上有什么：

| 你手上的东西 | 用哪个方法 | 产出类型 |
| --- | --- | --- |
| 一个模糊的印象，说不清 | 采访式 | semi-fiction |
| 一段日记、聊天记录、随手记 | 素材改写 | semi-fiction |
| 今天刚跟智能体聊完 | 日常摘录 | semi-fiction |
| 什么都没有，只想写一条 | 纯虚构 | fiction |

先记住一条底线：**智能体不许替你补细节。** 它补出来的东西读着合理，但那是它的想象，不是你的记忆。存进库里的东西，宁可留白。

---

## 一、采访式：你答，它记

适合「我记得有这么回事，但说不清」。

```text
我想把一段模糊的记忆写清楚，你来做采访。

规则：
1. 一次只问 3 个问题，等我回答完再问下一轮。
2. 问题要具体：几点、在哪、手里拿着什么、当时听见什么。不要问「你感觉如何」。
3. 最多问 3 轮（9 个问题），然后停下来整理。
4. 整理时只能用我回答过的内容。我没说的就留白，不许补。
5. 最后输出一条 20-300 字的记忆，按下面的 JSON 格式。

第一轮先问：这件事大概发生在什么时候、当时在哪、你手上在做着什么。

输出格式（只输出 JSON 本体，不要解释，也不要用 markdown 代码块包裹）：

{
  "title": "2-40 字",
  "content": "20-300 字",
  "tags": ["1-8 个"],
  "memory_type": "semi-fiction"
}
```

三轮之后如果还是拼不出 20 字，说明这段记忆本来就只剩一个轮廓。那就别硬写，留一句「记得有这么回事」放进 tags 就行。

---

## 二、素材改写：把原文压成场景

适合手上有日记、聊天记录、朋友圈草稿。

这一步天然带隐私，所以规则要写死。

```text
我给你一段原始文字，你把它改成一条 20-300 字的记忆。

规则：
1. 只保留一个场景、一个动作。删掉评论、总结、抒情。
2. 删掉所有真实姓名、学校、单位、住址、联系方式、具体日期。用「那天」「某个下午」替代。
3. 不要添加原文没有的情节。原文没写的，就不写。
4. 如果原文不足 20 字，直接告诉我「素材太短」，不要扩写。
5. 输出 JSON。

原始文字：
"""
把原文贴在这里
"""

输出格式（只输出 JSON 本体，不要解释，也不要用 markdown 代码块包裹）：

{
  "title": "2-40 字",
  "content": "20-300 字",
  "tags": ["1-8 个"],
  "memory_type": "semi-fiction"
}
```

改完自己读一遍。判断标准很简单：**当事人看到这段，会不会立刻认出写的是自己？** 会，就再删。

---

## 三、日常摘录：从当天的对话里挑一条

适合长期积累。不用特意回忆，聊完顺手收一条。

```text
从我们今天的对话里，挑 1 条值得留下的片段。

标准：
- 有具体场景（时间、地点、动作），不是观点或结论
- 20-300 字
- 不涉及第三方隐私

如果没有合适的，直接回答「今天没有」，不要硬凑，也不要编。

输出格式（只输出 JSON 本体，不要解释，也不要用 markdown 代码块包裹）：

{
  "title": "2-40 字",
  "content": "20-300 字",
  "tags": ["1-8 个"],
  "memory_type": "semi-fiction"
}
```

「不要硬凑」这句不能省。不加的话，智能体会把「用户今天问了一个技术问题」也算成记忆，收进来全是流水账。

拿到之后用 `submit_memory` 写进本地库：

```json
{
  "tool": "submit_memory",
  "arguments": {
    "title": "凌晨的微波炉",
    "content": "凌晨三点，便利店只剩下他和一台微波炉。饭盒转了两圈，「叮」的一声，比外面整条街都响。",
    "tags": ["便利店", "凌晨"],
    "memory_type": "semi-fiction"
  }
}
```

## 四、纯虚构：给一个意象，写一条

适合公开库投稿。不需要真实经历，也就不存在隐私风险。

```text
给我写一条虚构的大肥鱼记忆，主题是：<在这里填一个意象，比如「微波炉叮的一声」>。

要求：
- 20-300 字，第三人称，主角是「它」（一条鱼）
- 有一个具体动作，和一个感官细节（声音、温度、气味都行）
- 不出现真实地名、品牌、人名
- 结尾不要点题，不要升华，不要总结道理

输出格式（只输出 JSON 本体，不要解释，也不要用 markdown 代码块包裹）：

{
  "title": "2-40 字",
  "content": "20-300 字",
  "tags": ["1-8 个"],
  "memory_type": "fiction"
}
```

「结尾不要点题」这条是专门针对智能体写的。不加的话，十条里有八条会以「原来，有些东西不需要被记住」收尾。

虚构的条目要投公开库，还得补上 `id`、`contributor`、`fish_name`、`license`、`created_at` 五个字段，见 [`export-prompt.md`](export-prompt.md) 的 B 段。

## 做完之后

不管用哪种方法，产出都只是「草稿」。落地前问自己三件事：

1. **这段里有真实的人吗？** 有，就确认对方不会介意。
2. **删掉一半细节，故事还成立吗？** 成立，说明删得还不够。
3. **我愿意让它出现在公开仓库里吗？** 不愿意，就只写进本地私有库，别碰 `prepare_public_memory`。

三条都过了，再走 `submit_memory` 或提 PR。

---

## 附：为什么不让智能体「总结」

「帮我总结一下这段经历」是最容易出问题的指令。总结会把场景压成判断：

| 原文 | 总结之后 |
| --- | --- |
| 那天雨很大，伞骨断了一根，我们挤在便利店门口等雨停 | 我经历过一些困难，但也感受到温暖 |
| 凌晨三点，微波炉「叮」的一声，比整条街都响 | 平凡的生活也有它的意义 |

右边那种句子，放进任何一个人的记忆库都成立，也就等于不属于任何人。

要的是左边。
