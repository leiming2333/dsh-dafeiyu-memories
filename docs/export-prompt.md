# 让另一个助手导出记忆

换设备、换工具、或者同时用好几个 agent 时，记忆会散在各处。这里有两段提示词，直接复制给对方就行。

> 不知道记忆散在哪，先看 [find-memory.md](find-memory.md) 盘点一遍 —— 只列路径，不读内容。

两段的用途不同，别混：

- **A：导进你的私有库** —— 给自己的另一台机器、另一个助手用，内容可以保留真实细节。
- **B：导成公开投稿** —— 准备提 PR 进公开库，CC0，公开后收不回来。

---

## A. 导成可导入的私有记忆

适合：换电脑、合并多个 agent 的记忆、把旧会话里的东西收进 `dafeiyu-memories`。

### 提示词

```text
我要把记忆迁移到另一个记忆库，需要你把我们过去的对话整理成 JSON。

要求：
1. 只写对话里真实出现过的内容。不要编造，不要替我把细节补完整。
2. 每条 20-300 字，写一个具体场景，不要压缩成一句总结。
3. 最多 30 条，按时间从早到晚排。
4. 拿不准的信息就删掉，不要猜。
5. 不要包含真实姓名、学校全名、单位全名、住址、手机号、邮箱、QQ、微信号、群号。涉及第三方的部分，改写或跳过。

输出格式（只输出 JSON 本体，不要解释，也不要用 markdown 代码块包裹）：

{
  "format": "dsh-fish-memory/export@1",
  "memories": [
    {
      "content": "20-300 字的具体片段",
      "title": "可选，2-40 字，不写就自动取正文前 16 字",
      "created_at": "YYYY-MM-DD，不确定就省略",
      "half_life_days": 30,
      "long_term": false
    }
  ]
}

`long_term` 只有在这条属于「长期有效的事实」（比如我的固定习惯）时才写 true，其余都写 false。
```

### 拿到文件之后

1. 保存成 `dafeiyu-export.json`。
2. 放进数据目录的 `exports/` 下：

   ```
   ~/.dsh/data/dafeiyu-memories/exports/dafeiyu-export.json
   ```

   数据目录不一定是这个路径，用 `get_memory_stats` 返回的 `data_dir` 确认。

3. 调 `import_from_fish_memory`：

   ```json
   { "tool": "import_from_fish_memory", "arguments": { "path": "dafeiyu-export.json" } }
   ```

   也可以直接把 JSON 内容塞进 `payload`，省掉存文件这一步。

4. 看返回值：`imported` 是导入条数，`skipped` 是重复或太短被跳过的条数。

5. 用 `get_memory_stats` 核对总数。

### 导入时会怎么处理

- 正文不足 20 字的直接跳过，不会报错中断。
- 按正文指纹去重，同一段文字导两遍只会留一条。
- `source` 固定写成 `fish-memory`，`visibility` 固定 `private`。
- 超过 300 字的正文按字符截断（不是按字节，emoji 不会被切一半）。
- 落了盘也不会进公开库，也不会进 `dist/`。

## B. 导成公开投稿

适合：想让某段记忆进公开库的时候。这一步的前提是你已经想清楚 CC0 意味着什么。

### 提示词

```text
我在给一个公开记忆库投稿，这个库是 CC0 的：提交后任何人可以商用、修改、不署名，而且不可撤回。

请从我们的对话里挑 1-3 个适合公开的片段，按下面的格式输出。

硬性要求：
1. 20-300 字，虚构或半虚构。真实经历必须改掉细节，不能原样搬。
2. 不能出现任何能定位到真人的信息：姓名、学校、单位、住址、联系方式，也不要写「具体日期 + 具体地点」这种组合。
3. 不涉及可识别的未成年人，不消费他人的创伤。
4. contributor 一律写「匿名」。
5. 只输出 JSON 数组本体，不要解释，不要加注释，也不要用 markdown 代码块包裹。

格式：

[
  {
    "id": "0001",
    "fish_name": "大肥鱼",
    "contributor": "匿名",
    "title": "2-40 字",
    "content": "20-300 字",
    "tags": ["1-8 个，每个不超过 16 字"],
    "memory_type": "fiction 或 semi-fiction",
    "license": "CC0-1.0",
    "created_at": "YYYY-MM-DD"
  }
]

如果我说了起始编号，从这个编号往后排；没说就从 0001 开始。
```

### 拿到结果之后

1. 自己读一遍，重点看两件事：有没有能指向真人的细节，当事人看到会不会认出自己。
2. 对照 `docs/review-checklist.md` 逐项过。
3. 每条存成 `memories/<id>.json`，跑 `python scripts/check_memory.py`。
4. 提 PR。

工具里的 `prepare_public_memory` 只处理**本地已有的记忆**。如果这条记忆还在别的助手那里，先用 A 段导进来，再走 `prepare_public_memory` —— 它会做一遍强制过滤，比手工改稳。

---

## 两句提醒

**别让助手「总结」你的记忆。** 总结会把具体场景压成抽象判断，而公开库收的恰恰是场景。「那天雨很大，伞骨断了一根」比「我经历过一些困难」有价值得多。

**导出前先问自己要不要。** 记忆库不是备份盘，收进去的东西越多，翻起来越像流水账。一次导 10-30 条，比一次导 200 条有用。
