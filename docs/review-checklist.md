# 公开记忆审核清单

两条路径都用这份清单：**投稿人自查**（提 PR / 提 Issue 前）和**维护者复核**（合并前）。

原则只有一句：**宁可少收一条，也不收一条会让人被认出来的记忆。**

---

## 一、投稿人自查（提交前逐项打勾）

### 1. 内容

- [ ] 正文 20-300 字，是一个完整的短片段，不是一句口号。
- [ ] 标题 2-40 字，能看出这条记忆讲什么。
- [ ] 标签 1-8 个，每个 ≤16 字，不重复；优先用具体场景词（「弹幕」「凌晨」「第一次」），少用泛词（「生活」「日常」）。
- [ ] `memory_type` 是 `fiction`（完全虚构）或 `semi-fiction`（半虚构，有真实经历打底但细节已改写）。
- [ ] 读一遍：如果把这条发给当事人，他会不会立刻认出「这写的是我」？会 → 改。

### 2. 隐私（最容易翻车的地方）

逐项确认**没有**出现：

- [ ] 真实姓名、网名、ID、QQ 号、微信号、群号。
- [ ] 手机号、邮箱、身份证号（任何一段都不行）。
- [ ] 具体到门牌号的住址：省市区 + 路/街 + 小区 + 楼栋单元室。
- [ ] 学校全名（「XX 大学」「XX 附中」都算），包括缩写到能唯一指向的程度。
- [ ] 单位全名（公司、医院、银行、研究所、工作室）。
- [ ] 能定位到个人的时间 + 地点组合（「去年 3 月 12 日，XX 路口」这类）。
- [ ] 照片、截图、录音里的可识别信息（本仓库只收文字）。
- [ ] 第三方（朋友、家人、同事）的隐私 —— 他没有同意被写进来。

> 脚本只能挡住「格式明显」的信息，挡不住「你写得太具体」。第 2 项和第 6 项靠人眼。

### 3. 权利

- [ ] 这条记忆是我自己写的，或者我有权处置。
- [ ] 没有整段复制别人的文字、歌词、书摘、聊天记录。
- [ ] 我理解提交即按 **CC0-1.0** 放弃著作权，任何人可以任意使用、修改、商用，且**不可撤回**。
- [ ] 我理解公开后已经被 fork / 下载 / 索引的副本，维护者无法收回。

### 4. 未成年人与敏感场景

- [ ] 记忆里没有可识别的未成年人信息。
- [ ] 不涉及性、暴力、自伤、违法行为的**具体可模仿细节**。
- [ ] 不涉及他人的创伤经历（除非已充分虚构化，且不指向任何真实的人）。

### 5. 格式

- [ ] 文件放在 `memories/` 下，文件名是四位数字，如 `0007.json`。
- [ ] `id` 与文件名一致，且没有被别的文件占用（`python scripts/check_memory.py` 会查重）。
- [ ] `license` 是 `CC0-1.0`，一个字符都不能改。
- [ ] 只包含 9 个公开字段，没有多写 `source`、`visibility`、`mood_snapshot` 之类的私有字段（`additionalProperties: false`）。
- [ ] `contributor` 写「匿名」，或者一个你愿意公开的昵称（不要写真实姓名）。
- [ ] 本地跑过 `python scripts/check_memory.py`，输出 `0 失败`。

---

## 二、维护者复核（合并前）

### 1. 自动化

- [ ] `validate-memories` 这个 Action 是绿的。
- [ ] `id` 没有和已有条目冲突；如果冲突，确认是投稿人重复提交还是编号撞车。
- [ ] `dist/` 没有被手动改动（应该由 `build-index` 自动生成）。

### 2. 人眼复核（自动化替代不了的部分）

- [ ] 通读正文，判断是否「过于具体」：地点、时间、职业、家庭结构、身体特征、口头禅的组合，是否会让人被同事/同学认出来。
- [ ] 检查隐喻式隐私：不写名字，但写了「我们组只有两个前端，另一个刚休产假」—— 这等于写名字。
- [ ] 检查 `semi-fiction` 的边界：真实骨架保留到什么程度？如果骨架本身就足以定位，退回让作者改写。
- [ ] 检查是否在消费他人苦难：疾病、事故、家庭变故、校园事件。
- [ ] 检查是否有隐性广告、引流、联系方式变体（「主页有」「看简介」「私信我」）。
- [ ] 检查语言：简体中文为主，允许方言词，但不收纯引流文案、募捐、政治口号。

### 3. 合并

- [ ] PR 模板里三个勾选框都勾了：CC0、隐私、未成年。
- [ ] 提交信息用 `feat(memories): 新增 0007 <标题>` 这种格式。
- [ ] 合并后确认 `build-index` 跑过，`dist/memories.array.json` 里能搜到新条目。
- [ ] 如果作者要求撤回，且尚未被广泛 fork：删文件 + 重跑聚合 + 在 PR 里说明。已 fork 的部分无法处理，这一点在 PRIVACY.md 里已写明。

## 三、常见的「差一点就过」案例

| 写法 | 问题 | 改法 |
| --- | --- | --- |
| 「我在杭州某互联网公司做前端」 | 城市 + 岗位 + 行业，圈内可定位 | 「我在一个做地图的小团队里切图层」 |
| 「我们班主任姓王，教数学」 | 姓 + 科目 + 学校场景 | 「班主任教数学，粉笔灰总落在袖口」 |
| 「去年双十一，我在XX大学南门」 | 时间 + 学校 + 地点 | 「某个促销节的晚上，我在校门口等一份凉掉的炒饭」 |
| 「他 QQ 是 1234****」 | 直接泄漏 | 删掉，或写「他把号码写在纸条上，我没存」 |
| 「我妈在市一院住院」 | 医院 + 家庭关系 | 「家里有人在医院住了很久，走廊的灯整夜不关」 |

一个改稿方法：把地点、时间、职业这些细节先删掉，再读一遍，看故事还成不成立。
